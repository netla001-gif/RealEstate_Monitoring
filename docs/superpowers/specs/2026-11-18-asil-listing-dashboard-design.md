# 아실 매물증감 대시보드 — 설계

## 목적
전국 시/도·구/군의 매매·전세·월세 매물 수 증감을 한눈에 훑어보는 개인용 대시보드.
2023-11-01부터의 이력을 쌓고 매일 갱신. 맥이 꺼져 있어도 돌아가야 함.

- 목표: 전국 흐름 파악 (어디서 매물이 쌓이고/빠지는지), 일·주·월 단위 전환
- 비목표: 단지(아파트) 단위, 매물 가격, 알림
- 안티목표: 아실에 과도한 요청 (차단 위험), 서버 운영 부담

## 접근 방식
1. Streamlit + SQLite (로컬) — 맥이 꺼져 있으면 수집 안 됨 → 탈락
2. FastAPI + React — 개인 대시보드엔 과함 → 탈락
3. **GitHub Actions + 정적 페이지 (선택)** — 서버 불필요, 어디서든 열람. Actions에서 asil.kr 접근 확인 완료 (HTTP 200).

## 데이터 소스 (비공식 API)
- 지역 목록: `/app/data/data_deal_count.jsp?mode=0&deal=1&...` → 시/도 코드,
  `mode=1&area=<시도코드>` → 구/군 코드. 하드코딩하지 않고 매번 조회.
- 시계열: `/app/data/data_offer_sum.jsp?area=<코드>&deal=1&mode=2&sY=2023&sM=11&eY=<올해>&eM=<이번달>`
  → JS 응답 속 `listData[i]={"Date":"YY/MM/DD","VM":매매,"VJ":전세,"VW":월세,...}` 를 정규식으로 추출.
- 요청 간 1초 대기, 약 270회/일.

## 구성
- `collect.py` — 전 지역 시계열을 받아 `data/listings.csv`(date, code, name, level, sale, jeonse, wolse)에 upsert.
  - CSV 없음(최초): 2023-11-01부터 전체 수집.
  - 이후 매일: 지난달 1일~오늘만 수집해 같은 (date, code)는 덮어쓰고 새 날짜는 추가.
    한 달 여유를 두는 건 며칠 수집이 빠져도 자동 복구되게 하기 위함.
  - 요청 수는 어느 쪽이든 지역당 1회(약 270회)로 같고, 응답 크기만 줄어듦.
- `.github/workflows/collect.yml` — 매일 KST 07시 + 수동 실행. 변경 있으면 커밋·푸시.
- `index.html` — CSV를 fetch해 렌더. 일/주/월 선택 → 각 지역의 기간 증감률(%) 계산.
  - 상단: 시/도 증감률 히트맵(지역 × 매매/전세/월세)
  - 시/도 클릭 → 해당 구/군 순위표
  - 지역 클릭 → 매매·전세·월세 추이 라인 차트
- GitHub Pages로 공개 배포 (저장소 공개 승인됨).

## 빌더에게 맡김
차트 라이브러리 선택(CDN 하나), 색상, 테이블 정렬 방식.
